# Visitor outcomes

The entry view keeps the manufacturing cell visible. The introduction gives three routes with distinct outcomes:

| Element | Intended outcome |
| --- | --- |
| Product introduction | Understand the assembly before judging its manufacturing process. |
| Exploded view | Identify a component, see its function and distinguish incoming, cell and downstream work. |
| System filter and isolation | Inspect small or obscured components without searching eighteen labels or overlapping geometry. |
| Follow into assembly | Connect the selected physical part to its work location and operation. |
| Run controls above the scene | Set a scenario, then watch its consequences without scrolling away from the simulation. |
| Shift planner | Change required output and compare resource demand and lost production. |
| Evidence details and exports | Inspect assumptions and reproduce a study. |

The default target is 105 accepted frames in 420 available minutes, a 240-second required takt. The existing 192.6-second automatic-handling cycle is an assumed baseline, not a measured physical minimum. Whole-drone downstream assembly remains a separate extension of the frame-cell route.

Existing Three.js OrbitControls, Raycaster and the established product geometry are reused. No new animation framework, decorative hero model, stock factory image or unrelated template is introduced. Component purpose copy stays separate from manufacturing context.
